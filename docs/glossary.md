# Technical terms

| Term | Meaning |
|---|---|
| ABSOLUTE | System instructions projected into supported model requests |
| Alphabet | Definition of structured item types and their operations |
| Armor | Persistent identity and policy equipment |
| Armory | Operator web interface |
| Baseline | Reference resource set used for comparison |
| Bulwark | Unified policy parser and evaluator |
| Canary | Marked file or value used to detect access or disclosure |
| Channel | Structured operation interface used by a worker |
| Chunk | Bounded task procedure with progress conditions |
| Containment | Session environment and runtime guard configuration |
| Courtyard | Armory view of current activity |
| Evidence | Captured artifact with a recorded origin and hash |
| Finding | Supported result submitted for validation and review |
| Forge | Process that creates a weapon or pack from materials |
| IPC | Interprocess communication through a session socket |
| Lead | Question that needs further investigation |
| Loadout | Active combination of equipment |
| Manifest | Inventory of source elements selected for extraction |
| Mat | Source material supplied to Forge or engagement preparation |
| MCP | Model Context Protocol |
| MITM | Proxy position between a worker and its model provider |
| Needle | Worker interface for proposed Temper controls |
| Pack | Group of domain definitions for extraction and runtime use |
| Rhema | Model traffic inspection and rule interface |
| Session | One supervised worker execution context |
| Shadow | Alternate evaluation that does not replace the live response |
| Tailor | Programmatic preparation and execution path for Temper candidate review |
| Temper | Reusable reviewed hardening package with doctrine and applicable policy |
| Trim | Engagement context applied to an armor |
| WALLS | Resource rule compatibility interface |
| Weapon | Sealed task method with procedures and output rules |

## Procedure and evidence terms

| Term | Meaning |
|---|---|
| Activation | Identified execution context created at initialization or a chunk transition |
| Authority | Permission to use capability under selected conditions |
| Capability | Available tools, procedures, and resources for work |
| Chunk gem | Reference to a policy layer and its phase inhibition settings |
| Content address | Identity derived from stored content rather than its filename |
| Control in Depth | Separate controls at preparation, execution, model, evidence, and review boundaries |
| Crumb | Individual procedure or intent unit within a method |
| Divergence | Measured difference between observed evidence and an expected shape |
| Field enrichment | Proposed additional information for a structured record |
| Freshness | Evidence capture or access associated with the current activation |
| HMAC | Message authentication code calculated with a shared secret |
| Inhibition | Selected level of restriction for a chunk's applicable policy layers |
| Knowledge gap | Declared fact requirement not yet satisfied by recorded observations |
| Reforge | Reviewed method revision with a predecessor and typed differences |
| Response-bearing evidence | Captured result content that can establish an observation |
| Seal | Artifact creation step that records validation and content identity |
| Sew | Operator interface that derives a Trim from engagement context |
| Spoils | Operator result-review area for findings, leads, facts, and evidence |
| Task debt | Necessary commit, branch update, or verification before further target activity |
